# Replit Build Prompt: Redeemer House Recovery Housing Resident Management System

Build the foundational framework for a standalone **Redeemer House Recovery Housing Management Application**.

This application is completely separate from Corazon Connect and should have its own database, authentication, permissions, resident records, payment workflows, housing management structure, and reporting framework.

The purpose of the application is to manage residents living in Redeemer House recovery homes and give staff a centralized place to view each resident's housing history, payments, recovery progress, documentation, compliance information, medications, testing, assessments, case notes, and other program activity.

The architecture should be built to support multiple Redeemer House locations and future growth.

Prioritize:

* Database architecture
* Resident profile structure
* Multi-house functionality
* Permissions
* Audit history
* Modular reusable components
* Mobile accessibility
* Reporting readiness
* Secure document management
* Future payment integrations

Do not focus heavily on final visual design yet. Build the framework correctly first.

# 25. SECURITY

Treat all resident information as confidential.

Implement:

* Secure authentication
* Role-based permissions
* Session protections
* Encryption in transit
* Encryption at rest where appropriate
* Secure file storage
* Audit logging
* Soft deletion
* User access history
* Strong password requirements
* MFA-ready architecture
* Least-privilege access

Do not expose resident records through public URLs.

Do not store raw payment card or banking credentials.

Highly sensitive information such as medication records, UA results, recovery notes, and legal information should have additional access controls.

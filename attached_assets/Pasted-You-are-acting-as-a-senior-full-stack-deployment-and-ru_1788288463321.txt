* package.json scripts
* build commands
* start commands
* runtime commands

* .replit configuration
* replit.nix or equivalent environment configuration, if present
* environment variables and secrets
* database initialization

* frontend build output
* backend server startup
* API routes

* Node version

1. Diagnose before modifying.
2. Do not rewrite large working sections of the application unless absolutely necessary.
3. Identify the exact error or failure point.
4. Trace the error backward to its root cause rather than applying temporary patches.

11. Do not expose, remove, or hard-code secrets.

ROOT ERROR:
State the primary error preventing deployment.

WHERE IT OCCURS:
Build, startup, database initialization, frontend, backend, routing, authentication, environment configuration, or another location.

ROOT CAUSE:
Explain what is causing it.

PROPOSED FIX:
Explain the minimum changes necessary.

RISK:
Explain whether the fix could affect existing application functionality or data.

Then implement the safest fix.

After making changes, run the appropriate production-equivalent commands and verify:

* dependencies install successfully
* application builds successfully
* production start command executes successfully
* server stays running
* expected port is listening
* database connection succeeds
* application homepage loads
* authentication loads
* major API routes initialize without crashing

If the first issue exposes another runtime issue, continue debugging sequentially until the application reaches a stable deployable state.

Do not declare the issue resolved merely because the code compiles. The application must successfully start under production-like conditions.
